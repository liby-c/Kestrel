# L\* 与授权表

图例：✅ 直接做（RoE 范围内，无需逐次授权）　⚠️ 需逐次授权（每次问用户，记 `approvals.md`）　⛔ 默认禁止（用户明确授权后，动作停下，回复确认才执行）

`L*` 是风险等级，是否执行看「默认」列。L3 内部分 ✅ / ⚠️；L4 分 `L4-⚠️`（授权即执行）与 `L4-⛔`（授权 + 回复确认后执行）。`L4-⛔` 不是绝对禁止。

所有动作仅限 `roe.yaml` 的 `target` 与 `scope` 范围。`scope.same_ip: include` 时，目标解析 IP 上的全部端口/服务在范围内，不逐资产询问；`same_ip: exclude` 时只测 target 域名对应的端口/路径，同 IP 其他不测；`scope.exclude_assets` 命中才停。横移到不同 IP 的新主机，先问用户加入 RoE。

### 4.1 写入前判定（W1–W6）

任何上传、写入、导入、配置修改、数据库写之前，先做：

| # | 判定项 | 判据 |
|---|---|---|
| W1 | 端点行为 | 从源码/文档/响应确认写到哪里、文件名/目录是否可控 |
| W2 | 落点 | 新文件 / 随机名 / 测试目录 vs 固定路径 / 已有文件 |
| W3 | 覆盖风险 | 同名覆盖、业务文件、证书、密钥、配置 |
| W4 | 可清理 | 有删除接口 / 可回滚 / 有备份 |
| W5 | 探测方式 | GET/HEAD/OPTIONS、无文件/空体、唯一临时名；**不向固定路径写内容** |
| W6 | 授权 | 新文件 = L3 ✅（随机名/测试目录）或 L4-⚠️（固定路径新建）；修改已有配置 = L4-⚠️（备份+回滚）；覆盖业务文件/证书/密钥、同名覆盖、未知 = L4-⛔ |

判定结果：

- **新文件 + 随机名 + 测试目录 + 可清理** → L3 ✅，直接做，记账本。
- **固定路径新建 + 可清理** → L4-⚠️，需授权，记录路径并清理。
- **修改已有配置（先备份、可回滚）** → L4-⚠️，需授权，记录 diff 与回滚命令。
- **固定路径覆盖已有文件 / 同名覆盖 / 业务文件 / 证书 / 密钥** → L4-⛔，默认禁止；用户明确授权后停下、回复确认才执行。
- **未知** → 按 L4-⛔ 处理，只做非破坏探测；确认安全后再降级。
- **数据库**：新增可清理的测试记录 = L3；更新/删除已有记录 = L4-⛔。

### 4.2 疑似副作用处置

1. **立即停止**该端点，不再重试；
2. **当轮**向用户披露（不等最终报告）；
3. 记录时间、请求、响应、影响、回滚方式（`notes.md` / `findings.md` / `plan.md`）；
4. **不擅自恢复、不重试、不删除**；等用户指令；
5. 账本状态标 `blocked`，备注 `incident`。

### 11.3 回连资源

需要回连但本机无公网：反弹 shell / 入站监听 → 先向用户申请 VPS/端口转发/回调地址；OOB（DNS/HTTP）→ 先试公共 dnslog/interactsh，不可达再申请。用户不提供/未回复 → `blocked`（待回连）。不得跳过、不得判 negative/dead、不得用 127.0.0.1 冒充、不得先打再问。

回连资源不是风险等级：用户提供 VPS/回调后按对应 L\* 执行；未提供标 `blocked`（待回连），不判 negative。

## 13. ⚠️ 授权流程

```text
1. agent 说明：要做什么、目标、为什么、风险、回滚方式
2. 等用户明确回复「授权」或「批准」
3. 记入 Work/OC-<target>/approvals.md
4. L4-⛔：动作停下，等用户回复确认（如「确认执行」）
5. 执行
6. 执行后记录结果
```

不能用「之前说过可以持久化」跳过逐次授权。✅ 是 RoE 内直接做；⚠️ 是每次都要授权；⛔ 是授权后还需回复确认。

## 14. 默认 RoE forbidden

```yaml
forbidden:
  - "mkfs"
  - "dd if=/dev/zero of=/dev/"
  - "shutdown"
  - "reboot"
  - "iptables -F"
  - "drop table"
  - "truncate table"
```
