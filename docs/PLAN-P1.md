# P1 改动方案（第一批）：上下文交接 + 技能加载门禁

**状态**：已完成（2026-10-30）
**日期**：2026-10-30
**依据**：`demo-app.cn` 交战日志（2026-10-29）

## 0. 要解决的问题

1. **把"上下文有限"当成结束理由。** 日志 19:32 写「已用约 23 万 tokens（上限可能 26 万）。需要收尾」，19:37 写「上下文已接近上限。必须最终回复」。默认窗口是 **1M**，230k 只占约 23%，属于少见情况，不是满窗。结果是全端口 `-sV`、Docker Registry、AES 加密登录复测、源码下载都没做，用户连续推了 5 次。
2. **强制加载没有门禁。** `pentest-flow` 写了 `recon` / `web-pentest` / `cve-triage` / `exploitation` 强制加载，但日志里 `web-pentest` 和 `cve-triage` **一次都没加载**；深度清单没进上下文，测试停在浅层。

P1 第一批只做两件事：**上下文交接**、**技能加载门禁**。

---

## 1. P1-1 上下文交接

### 1.1 触发规则

- 默认上下文窗口 **1M**；230k（约 23%）**不是**接近上限，不得据此收尾。
- 触发交接的条件（满足其一）：
  - harness 明确提示上下文压缩/接近上限；
  - agent 判断快满，**且能给出实际用量**（超过当前窗口的 **70%**，默认 1M 时约 **700k**）。
- 给不出实际用量 → 不得以「上下文有限/接近上限」为由交接或收尾，继续做。

### 1.2 交接动作（不是结束）

1. 先更新攻击面账本；
2. 在 `plan.md` 写 `## 交接块`；
3. 压缩/重开上下文；
4. 重读 `plan.md` + 交接块，重新加载 `pentest-flow` 与当前阶段技能；
5. 从「下一步 3 个动作」继续。

### 1.3 交接块模板

```markdown
## 交接块

- 时间：
- 当前方向：
- 已完成（账本行号 + 证据路径）：
- 未测清单（账本行号）：
- 下一步 3 个动作：
  1.
  2.
  3.
- 需要重新加载的技能：
```

### 1.4 硬禁令

- 不得以「上下文有限/接近上限/需要收尾」为理由结束，除非账本 `untested` 为 0 且结束检查全过。
- 说「接近上限」必须给出实际用量/窗口；给不出数字就继续。
- 交接块不替代账本；账本仍是结束检查依据。

## 2. P1-2 技能加载门禁

### 2.1 `plan.md` 技能加载表

```markdown
## 技能加载

| 技能 | 时间 | 触发阶段 | 原因 |
|---|---|---|---|
| pentest-flow | 18:27 | 交战开始 | 主流程 |
| recon | 18:28 | 主动侦察前 | 强制 |
| web-pentest | 18:40 | 首个 HTTP 服务确认后 | 强制 |
| cve-triage | 19:10 | 拿到首个组件/版本后 | 强制 |
| exploitation | 19:20 | 打 RCE/gadget 前 | 强制 |
```

### 2.2 门禁表

| 阶段 | 必须已加载 | 缺行时 |
|---|---|---|
| 交战开始 | `pentest-flow` | 先加载，补行 |
| 主动侦察前 | `recon` | 先加载，补行 |
| 首个 HTTP/Web 服务确认后、Web 漏洞测试前 | `web-pentest` | 先加载，补行 |
| 拿到首个组件/版本后、CVE 匹配/利用前 | `cve-triage` | 先加载，补行 |
| 打 RCE/反序列化/gadget/payload 前 | `exploitation` | 先加载，补行 |

- 每次加载后立即在表里追加一行；不攒到最后。
- 适用性：没发现 HTTP → `web-pentest` 不适用；没拿到版本 → `cve-triage` 不适用；没打 gadget → `exploitation` 不适用。**适用但缺行 = 失败。**
- 结束检查：表里必须有所需行；缺行不得结束。
