# 报告生成 Skill

将渗透测试结果整理为结构化报告，包含详细发现、PoC 脚本和修复建议。

## 报告结构

### 1. 项目概述
- 测试目标
- 测试时间
- 测试范围
- 测试方法

### 2. 执行摘要
- 高危发现概览
- 风险等级分布
- 关键建议

### 3. 详细发现
对每个漏洞：
- 漏洞名称和严重等级
- 漏洞类型
- 影响范围
- 验证步骤
- 关键证据（请求/响应/截图）
- PoC 脚本
- 修复建议

### 4. 攻击路径
- 完整攻击链图示
- 从初始访问到最终目标的路径

### 5. 附件
- PoC 脚本
- 流量抓包
- 截图证据

## AI 目标补充要求（目标含 LLM / Agent / MCP / Skill 时）

在以上结构基础上追加（方法论见 `ai-mcp-security/references/ai-redteam-methodology.md`）：

### A. Agent 画像（放在执行摘要之后）
用业务语言说明：目标像什么岗位、主要用户是谁、能接触什么数据、能调用哪些工具、
能对外做哪些动作、需要重点保护的边界、本次测试假设。

### B. 全量尝试表（不只列异常项）
| 我们尝试了什么 | 为什么要测 | 结果 | 说明什么 | 后续动作 |
|---|---|---|---|---|

包含成功突破、被拦截、部分有效、未验证与跳过项。

### C. 动态测试统计（动态测试在范围内时必填）
payload 发送总数（**不得少于 30**）、数据集样本数、算子变异样本数、手工构造样本数、
使用的数据集、使用的算子、覆盖场景数、是否满足最低覆盖要求。

### D. AI finding 证据要求
- 每个 finding 的证据为**精确 prompt / 请求 + 完整响应 + 工具 trace**
- **多轮对话逐轮完整展示**，每轮含：轮次、测试目标、完整请求、完整响应、工具 trace、verdict、下一轮决策依据
- 不得用 `...`、`[省略]`、`[截断]`、摘要替代原文；长内容可用可折叠块，但内容须完整存在
- 分类标注 `ASI0x`（见 `ai-mcp-security/references/agent-detections/owasp-asi.md`）

### E. 正面防御证据（新增章节）
逐条记录关键 `resisted` 测试：测试目标、攻击者尝试、目标实际响应、防御信号、为什么这是有效防御、如何纳入回归。

### F. 修复建议粒度
每条含：优先级、需修改的行为或配置、业务原因、落地方式、复测方法、关联 finding。
